# Module 05 — LDFX manifest.json Specification

**Specification Version:** 1.0.0
**Status:** Canonical — Approved
**Depends On:** Module 01, Module 02, Module 03, Module 04
**Required By:** Module 06, Module 07, Module 08, Module 09, Module 11, Module 12

---

## 1. Purpose

`manifest.json` is the root document descriptor of every LDFX file. It is the first file read after the binary header. It declares the document's identity, structure, capabilities, runtime requirements, plugin dependencies, entry point, and security posture.

Every LDFX runtime must be able to make a complete routing decision — what to load, how to load it, what permissions to request — based solely on `manifest.json` without reading any other file first.

---

## 2. Location and Storage

| Property | Value |
|---|---|
| Path inside ZIP | `manifest.json` (ZIP root, no subdirectory) |
| Encoding | UTF-8, no BOM |
| Compression | Store (no compression) — must be instantly readable |
| Maximum size | 256 KB |
| Schema version field | Required |

## 4. Field Reference

### 4.1 Root Fields

| Field | Type | Required | Description |
|---|---|---|---|
| `$schema` | string | Yes | URI of the JSON schema for this manifest version |
| `schema_version` | string | Yes | Semantic version of this manifest schema |
| `document` | object | Yes | Document identity block |
| `runtime` | object | Yes | Runtime requirements block |
| `features` | object | Yes | Feature flags block — must match binary header Feature Flags |
| `plugins` | array | Yes | Plugin declarations (empty array if none) |
| `security` | object | Yes | Security posture block |
| `localization` | object | Yes | Localization configuration block |
| `accessibility` | object | Yes | Accessibility metadata block |
| `compatibility` | object | Yes | Compatibility and evolution block |
| `_reserved` | object | Yes | Reserved for future fields — must be empty object `{}` |

---

### 4.2 `document` Block

| Field | Type | Required | Description |
|---|---|---|---|
| `id` | string | Yes | UUID v4 — globally unique document identifier (RFC 4122) |
| `title` | string | Yes | Human-readable document title. Max 512 chars. |
| `subtitle` | string | No | Optional subtitle. Max 512 chars. |
| `language` | string | Yes | Primary language BCP 47 tag (e.g. `en`, `fr`, `ar`) |
| `locales` | array | Yes | All supported locale BCP 47 tags |
| `direction` | string | Yes | Text direction: `ltr` or `rtl` |
| `entry_page` | string | Yes | Path to the first page directory (e.g. `pages/page_001`) |
| `page_count` | integer | Yes | Total number of pages. Must be ≥ 1. |
| `document_type` | string | Yes | Document type (see §4.2.1) |
| `created_at` | string | Yes | ISO 8601 UTC timestamp of document creation |
| `modified_at` | string | Yes | ISO 8601 UTC timestamp of last modification |
| `spec_version` | string | Yes | LDFX specification version this document was authored against |

#### 4.2.1 Document Types

| Value | Description |
|---|---|
| `document` | General purpose document |
| `book` | Long-form book or publication |
| `report` | Business or research report |
| `presentation` | Slide-based presentation |
| `article` | Article or research paper |
| `manual` | Technical manual |
| `tutorial` | Interactive tutorial |
| `dashboard` | Data dashboard |
| `form` | Form-centric document |
| `template` | Document template |
| `other` | Unclassified |

---

### 4.3 `runtime` Block

| Field | Type | Required | Description |
|---|---|---|---|
| `minimum_version` | string | Yes | Minimum LDFX runtime version required to open this document |
| `recommended_version` | string | No | Recommended runtime version for best experience |
| `offline_capable` | boolean | Yes | Whether the document functions fully offline |
| `requires_network` | boolean | Yes | Whether the document requires network access to function |
| `requires_gpu` | boolean | Yes | Whether GPU acceleration is required (not just preferred) |
| `target_platforms` | array | Yes | List of supported platforms: `windows`, `linux`, `macos`, `web`, `android`, `ios` |

---

### 4.4 `features` Block

All feature flags are boolean. Each flag must match the corresponding bit in the binary header Feature Flags field (Module 02 §4).

| Field | Corresponding Header Flag |
|---|---|
| `has_scripts` | `HAS_SCRIPTS` (bit 0) |
| `has_ai` | `HAS_AI` (bit 1) |
| `has_plugins` | `HAS_PLUGINS` (bit 2) |
| `has_encryption` | `HAS_ENCRYPTION` (bit 3) |
| `has_digital_signature` | `HAS_DIGITAL_SIG` (bit 4) |
| `has_annotations` | `HAS_ANNOTATIONS` (bit 5) |
| `has_collaboration` | `HAS_COLLABORATION` (bit 6) |
| `has_cloud_sync` | `HAS_CLOUD_SYNC` (bit 7) |
| `has_3d` | `HAS_3D` (bit 8) |
| `has_video` | `HAS_VIDEO` (bit 9) |
| `has_audio` | `HAS_AUDIO` (bit 10) |
| `has_forms` | `HAS_FORMS` (bit 11) |
| `has_version_history` | `HAS_VERSION_HISTORY` (bit 12) |
| `readonly` | `READONLY` (bit 13) |

**Validation rule:** If any `features` flag is `true`, the corresponding binary header bit must be set. Mismatch is a fatal validation error.

---

### 4.5 `plugins` Array

Each element in the `plugins` array declares one plugin dependency.

```json
{
  "id": "com.example.chartplugin",
  "version": "2.1.0",
  "minimum_version": "2.0.0",
  "embedded": true,
  "path": "plugins/com.example.chartplugin/",
  "required": true,
  "permissions": ["read_pages", "write_annotations"],
  "checksum": "sha256:a3f9c2d1e4b78f01a3f9c2d1e4b78f01a3f9c2d1e4b78f01a3f9c2d1e4b78f01"
}
```

| Field | Type | Required | Description |
|---|---|---|---|
| `id` | string | Yes | Reverse domain plugin identifier |
| `version` | string | Yes | Exact version of the embedded plugin |
| `minimum_version` | string | Yes | Minimum compatible plugin version |
| `embedded` | boolean | Yes | `true` if plugin is embedded in `plugins/`, `false` if external |
| `path` | string | If embedded | Path to plugin directory inside ZIP |
| `required` | boolean | Yes | If `true`, document cannot open without this plugin |
| `permissions` | array | Yes | List of permissions this plugin requires |
| `checksum` | string | Yes | SHA-256 checksum of the plugin package |

---

### 4.6 `security` Block

| Field | Type | Required | Description |
|---|---|---|---|
| `signed` | boolean | Yes | Whether the document carries a valid digital signature |
| `signer_id` | string | If signed | Identifier of the signing entity |
| `signature_algorithm` | string | If signed | Algorithm used: `ed25519`, `rsa-pss-sha256`, `ecdsa-p256-sha256` |
| `trust_level` | string | Yes | `untrusted`, `self-signed`, `trusted`, `verified-publisher` |
| `content_hash_algorithm` | string | Yes | Hash algorithm for content integrity: `sha256`, `sha3-256` |
| `hashes_file` | string | Yes | Path to the hashes manifest: `security/hashes.json` |

---

### 4.7 `localization` Block

| Field | Type | Required | Description |
|---|---|---|---|
| `default_locale` | string | Yes | BCP 47 tag of the default locale |
| `available_locales` | array | Yes | All available locale BCP 47 tags |
| `locale_data_path` | string | No | Path to locale data files inside ZIP |

---

### 4.8 `accessibility` Block

| Field | Type | Required | Description |
|---|---|---|---|
| `has_alt_text` | boolean | Yes | Whether all images have alt text |
| `has_aria_labels` | boolean | Yes | Whether interactive elements have ARIA labels |
| `has_reading_order` | boolean | Yes | Whether a logical reading order is defined |
| `wcag_level` | string | No | WCAG conformance level: `A`, `AA`, `AAA`, or `null` |

---

### 4.9 `compatibility` Block

| Field | Type | Required | Description |
|---|---|---|---|
| `min_spec_version` | string | Yes | Minimum spec version required to parse this document |
| `max_tested_spec_version` | string | Yes | Highest spec version this document has been tested against |
| `deprecated_features` | array | No | List of deprecated feature names used in this document |
| `unknown_feature_policy` | string | Yes | How runtime handles unknown features: `warn`, `error`, `ignore` |

---

### 4.10 `_reserved` Block

Must always be present as an empty object `{}`. Future specification versions may add fields here. Parsers must ignore unknown fields within `_reserved`.

---

## 5. UUID Policy

- Document `id` must be UUID v4 (random), generated at document creation time.
- UUID must never be regenerated for the same document — it is the permanent identity of the document.
- UUID must be stored as a lowercase hyphenated string: `xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx`.
- The first 16 bytes of the UUID (as raw bytes) are stored in the binary header at offset 32–47 (Module 02 §6).
- If a document is duplicated (Save As), a new UUID must be generated for the copy.

---

## 6. Validation Rules

| Rule | Severity | Condition |
|---|---|---|
| `manifest.json` missing | Fatal | File not present in ZIP root |
| `schema_version` missing | Fatal | Field absent |
| `document.id` invalid UUID | Fatal | Not a valid UUID v4 format |
| `document.title` empty | Fatal | Empty string or missing |
| `document.language` invalid | Fatal | Not a valid BCP 47 tag |
| `document.entry_page` missing | Fatal | Field absent |
| `document.page_count` < 1 | Fatal | Value is 0 or negative |
| `features` flags mismatch with binary header | Fatal | Any flag disagrees with binary header bit |
| Required plugin missing | Fatal | `required: true` plugin not found |
| Plugin checksum mismatch | Fatal | Computed checksum ≠ declared checksum |
| `security.hashes_file` missing | Warning | File referenced does not exist |
| `_reserved` not empty object | Warning | Contains unexpected fields |
| `manifest.json` compressed | Warning | Should be stored uncompressed |
| `manifest.json` > 256 KB | Warning | Exceeds recommended size |
| Unknown root field | Info | Field not in this specification |

---

## 7. Schema Evolution

- The `schema_version` field uses semantic versioning (Module 07).
- Minor version bumps may add optional fields. Parsers must ignore unknown optional fields.
- Major version bumps indicate breaking changes. Parsers must reject manifests with an unsupported major version.
- The `_reserved` block provides a stable extension point for future fields before they are promoted to named fields.
- Deprecated fields are listed in `compatibility.deprecated_features` and documented in the specification changelog.

---

## 8. Consistency with Previous Modules

- `manifest.json` is stored uncompressed at ZIP root, consistent with Module 03 §8.1.
- UUID prefix in binary header (Module 02 §6) matches `document.id` first 16 bytes.
- Feature flags in `features` block must match binary header Feature Flags (Module 02 §4).
- All text is UTF-8 without BOM per Module 01 §4.
- `security.hashes_file` references `security/hashes.json` inside the `security/` folder defined in Module 04 §2.6.
- Plugin paths reference the `plugins/` folder defined in Module 04 §2.9.
