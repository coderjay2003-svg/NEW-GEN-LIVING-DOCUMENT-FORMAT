# Module 04 — LDFX Folder Structure Specification

**Specification Version:** 1.0.0
**Status:** Canonical — Approved
**Depends On:** Module 01, Module 02, Module 03
**Required By:** Module 05, Module 06, Module 08, Module 09, Module 10, Module 11, Module 12

---

## 1. Purpose

This module defines every official folder inside an LDFX package. For each folder, it specifies purpose, allowed file types, ownership, size recommendations, permissions, deletion policy, cache policy, synchronization policy, future compatibility, and mandatory vs optional status.

---

## 2. Folder Definitions

---

### 2.1 `metadata/`

| Property | Value |
|---|---|
| Mandatory | Yes |
| Owner | Author / Editor |
| Purpose | Stores all document metadata — identity, authorship, versioning, licensing, accessibility, localization |

**Allowed file types:**
- `metadata.json` — the single authoritative metadata file (see Module 06)

**Maximum size recommendation:** 512 KB. Metadata exceeding this indicates a design problem.

**Read permissions:** Runtime, Reader, Editor, Plugin (read-only)

**Write permissions:** Editor only. Runtime must not modify metadata except during explicit save operations.

**Deletion policy:** Must never be deleted. Document is invalid without `metadata/metadata.json`.

**Cache policy:** Not cached. Always read from source.

**Synchronization policy:** Always synchronized. Metadata changes trigger a sync event.

**Future compatibility:** Additional JSON files may be added inside `metadata/` in future versions. Parsers must ignore unknown files within this folder.

---

### 2.2 `pages/`

| Property | Value |
|---|---|
| Mandatory | Yes |
| Owner | Author / Editor |
| Purpose | Contains all page content, layout definitions, and the page index |

**Allowed file types:**
- `index.json` — ordered list of all pages with references
- `page_NNN/content.json` — content node tree for page NNN
- `page_NNN/layout.json` — layout definition for page NNN

**Page directory naming:** Zero-padded 3-digit minimum: `page_001`, `page_002`, ... `page_999`, `page_1000` (no zero-padding beyond natural length for counts > 999).

**Maximum size recommendation:**
- Per page directory: 50 MB (excluding embedded assets — assets are stored in `assets/`)
- Total `pages/` directory: No hard limit, but documents exceeding 2 GB of page content should be split

**Read permissions:** Runtime, Reader, Editor, Plugin (read-only unless plugin has page-write permission)

**Write permissions:** Editor, Runtime (during save)

**Deletion policy:** Individual pages may be deleted by the Editor. `pages/index.json` must always exist.

**Cache policy:** Rendered page output may be cached in `cache/`. Source page JSON is never cached.

**Synchronization policy:** Always synchronized. Page changes are the primary sync payload.

**Future compatibility:** Additional files may appear inside page directories in future versions. Parsers must ignore unknown files.

---

### 2.3 `assets/`

| Property | Value |
|---|---|
| Mandatory | No |
| Owner | Author / Editor |
| Purpose | Stores all binary and media assets referenced by pages, scripts, or AI content |

**Subdirectory structure:**

| Subdirectory | Allowed Types | Notes |
|---|---|---|
| `assets/images/` | JPEG, PNG, WebP, AVIF, GIF, SVG | SVG stored here as image asset |
| `assets/audio/` | MP3, AAC, OPUS, FLAC, WAV | WAV only for short clips |
| `assets/video/` | MP4 (H.264/H.265), WebM (VP9/AV1) | No raw uncompressed video |
| `assets/fonts/` | WOFF2, WOFF, TTF, OTF | WOFF2 preferred |
| `assets/vector/` | SVG, PDF (embedded vector only) | Interactive SVG allowed |
| `assets/3d/` | glTF, GLB, USDZ (future) | GLB preferred (self-contained) |
| `assets/data/` | JSON, CSV, Parquet | Structured data for charts/tables |

**Asset naming:** Assets must be named by their content hash (SHA-256, first 16 hex chars) plus original extension. Example: `a3f9c2d1e4b78f01.webp`. This enables deduplication and integrity verification.

**Maximum size recommendation:**
- Single asset: 2 GB (ZIP64 required above 4 GB)
- Total `assets/`: No hard limit

**Read permissions:** Runtime, Reader, Editor, Plugin (read-only)

**Write permissions:** Editor only

**Deletion policy:** Assets may be deleted if no page or script references them. Orphan detection is performed during document save.

**Cache policy:** Decoded asset data (decompressed images, decoded audio) may be cached in `cache/`.

**Synchronization policy:** Synchronized on change. Large assets use delta sync when supported by the sync engine.

**Future compatibility:** New subdirectories may be added for new asset types. Parsers must ignore unknown subdirectories.

---

### 2.4 `scripts/`

| Property | Value |
|---|---|
| Mandatory | No |
| Owner | Author / Editor |
| Purpose | Contains executable scripts that power interactive document behavior |

**Allowed file types:**
- `index.json` — script manifest listing all scripts, their entry points, and permission requirements
- `<script-id>.js` — JavaScript source (executed in sandboxed WASM runtime)
- `<script-id>.wasm` — Precompiled WebAssembly module

**Script ID format:** UUID v4, lowercase, no hyphens. Example: `a3f9c2d1e4b78f01a3f9c2d1e4b78f01`

**Maximum size recommendation:**
- Single script: 10 MB
- Total `scripts/`: 100 MB

**Read permissions:** Runtime only (scripts are never directly readable by plugins or external tools)

**Write permissions:** Editor only

**Deletion policy:** Scripts may be deleted if no page references them.

**Cache policy:** Compiled WASM modules may be cached in `cache/` after JIT compilation.

**Synchronization policy:** Synchronized on change.

**Security:** Scripts are executed only inside the LDFX sandboxed runtime. See Module 09 for full security policy.

**Future compatibility:** Additional script types (e.g., `.ldfxs` — LDFX native script) may be added in future versions.

---

### 2.5 `annotations/`

| Property | Value |
|---|---|
| Mandatory | No |
| Owner | Author / Runtime / Reader |
| Purpose | Stores user and system annotations — comments, highlights, bookmarks, review notes |

**Allowed file types:**
- `index.json` — annotation index
- `<annotation-id>.json` — individual annotation record

**Annotation ID format:** UUID v4

**Maximum size recommendation:** 50 MB total

**Read permissions:** Runtime, Reader, Editor, Plugin (with annotation-read permission)

**Write permissions:** Runtime, Editor, Plugin (with annotation-write permission)

**Deletion policy:** Annotations may be deleted individually. The `index.json` must always exist if the folder exists.

**Cache policy:** Not cached.

**Synchronization policy:** Synchronized. Annotation sync is lower priority than page sync.

**Future compatibility:** New annotation types may be added. Parsers must ignore unknown annotation type fields.

---

### 2.6 `security/`

| Property | Value |
|---|---|
| Mandatory | Yes |
| Owner | Security Engine |
| Purpose | Stores digital signatures, certificates, integrity hashes, and trust metadata |

**Allowed file types:**
- `signatures.json` — document-level digital signatures
- `certificates/` — subdirectory containing X.509 certificates in PEM format
- `hashes.json` — SHA-256 hashes of all document entries (integrity manifest)

**Maximum size recommendation:** 10 MB

**Read permissions:** Runtime, Security Engine

**Write permissions:** Security Engine only. Editor triggers security engine to update on save.

**Deletion policy:** Must never be deleted. Document integrity cannot be verified without `security/`.

**Cache policy:** Not cached.

**Synchronization policy:** Always synchronized. Security data is synchronized atomically with the document.

**Future compatibility:** Additional security files (e.g., quantum-safe signature files) may be added. See Module 09.

---

### 2.7 `cache/`

| Property | Value |
|---|---|
| Mandatory | No |
| Owner | Runtime only |
| Purpose | Stores runtime-generated temporary data — rendered page bitmaps, decoded assets, compiled scripts |

**Allowed file types:** Any runtime-generated binary or JSON file.

**Maximum size recommendation:** 500 MB (runtime must enforce this limit and evict LRU entries)

**Read permissions:** Runtime only

**Write permissions:** Runtime only

**Deletion policy:** Cache may be fully deleted at any time without affecting document integrity. The document must function correctly after cache deletion.

**Cache policy:** This folder IS the cache. Contents are never included in integrity hashes or synchronization.

**Synchronization policy:** Never synchronized. Cache is local to each device.

**Future compatibility:** Cache format is internal to the runtime and may change between runtime versions.

---

### 2.8 `thumbnails/`

| Property | Value |
|---|---|
| Mandatory | No |
| Owner | Runtime / Editor |
| Purpose | Stores pre-rendered thumbnail images for document preview in file browsers and editors |

**Allowed file types:**
- `cover.webp` — document cover image (recommended: 800×1200 px, WebP)
- `page_NNN.webp` — per-page thumbnail (recommended: 400×600 px, WebP)

**Maximum size recommendation:** 20 MB total

**Read permissions:** Runtime, Reader, Editor, OS file browser

**Write permissions:** Runtime, Editor

**Deletion policy:** May be deleted. Thumbnails are regenerated by the runtime on next open.

**Cache policy:** Thumbnails are themselves a cache of rendered content. Not cached further.

**Synchronization policy:** Synchronized for cover image only. Per-page thumbnails are not synchronized (regenerated locally).

**Future compatibility:** Additional thumbnail sizes or formats may be added.

---

### 2.9 `plugins/`

| Property | Value |
|---|---|
| Mandatory | No |
| Owner | Author / Plugin SDK |
| Purpose | Contains embedded plugin packages that the document requires to render or execute correctly |

**Allowed file types:**
- `index.json` — plugin manifest listing all embedded plugins
- `<plugin-id>/` — subdirectory containing a single plugin package

**Plugin ID format:** Reverse domain name notation. Example: `com.example.chartplugin`

**Maximum size recommendation:**
- Single plugin: 50 MB
- Total `plugins/`: 200 MB

**Read permissions:** Runtime, Plugin SDK

**Write permissions:** Editor, Plugin SDK (during plugin installation)

**Deletion policy:** Plugins may be removed if no page or script references them.

**Cache policy:** Compiled plugin WASM may be cached in `cache/`.

**Synchronization policy:** Synchronized. Plugin packages are included in document sync.

**Security:** Plugins execute inside the LDFX sandboxed runtime. See Module 09 and Module 12.

**Future compatibility:** Plugin package format is versioned independently. See Module 12.

---

### 2.10 `ai/`

| Property | Value |
|---|---|
| Mandatory | No |
| Owner | AI Engine |
| Purpose | Stores embedded AI models, knowledge bases, inference configurations, and AI-generated content metadata |

**Allowed file types:**
- `index.json` — AI asset manifest
- `<model-id>/` — subdirectory containing a single model or knowledge base
- `<model-id>/model.gguf` — quantized model in GGUF format (preferred for embedded models)
- `<model-id>/config.json` — model configuration

**Maximum size recommendation:**
- Single model: 4 GB (ZIP64 required)
- Total `ai/`: No hard limit (large AI documents are expected)

**Read permissions:** AI Engine, Runtime

**Write permissions:** AI Engine, Editor

**Deletion policy:** AI assets may be removed if no page or script references them.

**Cache policy:** Inference results may be cached in `cache/`.

**Synchronization policy:** Synchronized. Large models use delta sync.

**Future compatibility:** New model formats will be added as the AI landscape evolves. The `index.json` declares the format of each model.

---

### 2.11 `logs/`

**Decision: Logs folder is included.**

**Rationale:** Production-grade document runtimes require structured logging for debugging, audit trails, security event recording, and crash diagnostics. Excluding logs would make it impossible to diagnose runtime failures in deployed documents. Logs are runtime-managed, never included in integrity hashes, and never synchronized — they carry no security risk to the document itself.

| Property | Value |
|---|---|
| Mandatory | No |
| Owner | Runtime only |
| Purpose | Stores structured runtime session logs for debugging, audit, and diagnostics |

**Allowed file types:**
- `<session-id>.json` — structured JSON log for a single runtime session

**Session ID format:** UUID v4

**Log entry structure (per line, newline-delimited JSON):**
```json
{
  "ts": 1700000000,
  "level": "info",
  "module": "renderer",
  "msg": "Page 1 rendered in 12ms",
  "data": {}
}
```

**Log levels:** `debug`, `info`, `warn`, `error`, `fatal`

**Maximum size recommendation:** 10 MB total. Runtime must rotate and truncate logs when this limit is approached.

**Read permissions:** Runtime, Editor (for diagnostics display)

**Write permissions:** Runtime only

**Deletion policy:** Logs may be deleted at any time. Document integrity is not affected.

**Cache policy:** Not applicable.

**Synchronization policy:** Never synchronized. Logs are local to each device and session.

**Retention policy:** Maximum 10 session log files. Oldest are deleted when limit is exceeded.

**Future compatibility:** Log schema is versioned via a `schema_version` field in each log file.

## 3. Folder Permission Summary

| Folder | Author | Editor | Runtime | Plugin | Reader |
|---|---|---|---|---|---|
| `metadata/` | R | RW | R | R | R |
| `pages/` | R | RW | RW | R* | R |
| `assets/` | R | RW | R | R | R |
| `scripts/` | — | RW | R | — | — |
| `annotations/` | R | RW | RW | R* | R |
| `security/` | — | — | R | — | — |
| `cache/` | — | — | RW | — | — |
| `thumbnails/` | — | RW | RW | — | R |
| `plugins/` | — | RW | R | R | — |
| `ai/` | — | RW | R | — | — |
| `logs/` | — | — | RW | — | — |

`R` = Read, `W` = Write, `*` = With declared permission, `—` = No access

## 4. Validation Rules

| Rule | Severity | Condition |
|---|---|---|
| `metadata/` missing | Fatal | Folder not present in ZIP |
| `metadata/metadata.json` missing | Fatal | File not present |
| `pages/` missing | Fatal | Folder not present in ZIP |
| `pages/index.json` missing | Fatal | File not present |
| `security/` missing | Fatal | Folder not present in ZIP |
| `security/signatures.json` missing | Warning | File not present (document is unsigned) |
| `security/hashes.json` missing | Warning | File not present (integrity unverifiable) |
| Unknown folder at root | Info | Folder name not in known or reserved list |
| `cache/` present in new document | Warning | Author should not include cache in distributed document |
| `logs/` present in new document | Warning | Author should not include logs in distributed document |
| Asset in wrong subdirectory | Warning | e.g., image file found in `assets/audio/` |
| Plugin missing `index.json` | Fatal | `plugins/` present but `plugins/index.json` missing |
| AI folder missing `index.json` | Fatal | `ai/` present but `ai/index.json` missing |

## 5. Consistency with Previous Modules

- Folder structure is consistent with the container diagram in Module 03 §4.
- Feature Flags in Module 02 §4 map to optional folders: `HAS_SCRIPTS`→`scripts/`, `HAS_AI`→`ai/`, `HAS_PLUGINS`→`plugins/`, `HAS_ANNOTATIONS`→`annotations/`, `HAS_3D`→`assets/3d/`, `HAS_VIDEO`→`assets/video/`, `HAS_AUDIO`→`assets/audio/`, `HAS_FORMS`→pages content.
- All JSON files use UTF-8 without BOM per Module 01 §4.
- `security/` is required, consistent with Module 01 §6.3 and Module 09 (Security).
- `cache/` and `logs/` are system folders, consistent with Module 03 §6.
